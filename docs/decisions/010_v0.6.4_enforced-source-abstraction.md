# 010 — The music worker abstraction is enforced by tooling

<details>
<summary><b>한국어 — music worker 추상화는 도구로 강제한다</b></summary>

- **버전:** v0.6.4
- **상태:** 채택

### 맥락

저장소는 공개되어 있고, [001](./001_v0.5.0_music-worker.md)의 규칙 — 봇은 음악이 어디서 오는지 모른다 — 은 저장소의 어떤
것도 그와 다르게 말하지 않을 때만 지켜집니다. 코드, 주석, 커밋 메시지, 이슈, 릴리즈 노트 모두. 기억에만 의존한 규칙은 이미 한
번 빠져나간 적이 있습니다.

### 결정

규칙을 `yarn check:abstraction`이 기계적으로 검사합니다. 검사할 단어 목록은 글이 아니라 스크립트 안에 둡니다. pre-commit 훅이
stage된 파일을, commit-msg 훅이 메시지를, CI 워크플로가 push된 모든 범위를 검사합니다 — 마지막 것은 로컬에서 건너뛸 수 없습니다.
에이전트와 기여자도 여전히 diff를 직접 읽습니다. 스크립트는 단어를 잡을 뿐 암시를 잡지 못합니다.

### 결과

- 공개 기록은 음악 백엔드를 "music worker"로만 설명합니다.
- 특정 worker 구현에 대한 논의는 이 저장소에 아예 두지 않습니다.
- 가끔 무해한 단어가 검사에 걸려 다르게 표현해야 합니다.

## Context

The repository is public, and the rule from [001](./001_v0.5.0_music-worker.md) — the bot knows nothing about where
music comes from — only holds if nothing in the repository says otherwise: not the code, not a comment, a commit message,
an issue or a release note. A rule kept by memory alone had already slipped once.

## Decision

The rule is checked mechanically by `yarn check:abstraction`, against a list of terms kept in the script rather than in
prose: a pre-commit hook scans staged files, a commit-msg hook scans the message, and a CI workflow scans every pushed
range — the check that cannot be skipped locally. Agents and contributors still read their diffs; the script catches
terms, not hints.

## Consequences

- The public history describes the music backend only as "the music worker".
- Discussion of a particular worker implementation does not belong in this repository at all.
- Occasionally a harmless word trips the check and has to be phrased differently.
