### 맥락

대시보드는 고를 목록을 보여 줍니다 — 채널, 역할, 멤버, 저장소, GitHub 계정, 열린 PR. 목록은 불완전할 수 있습니다. 저장소에 App이
아직 설치되지 않았거나, 자격 증명이 없거나, 항목이 닫혔거나, 멤버가 캐시에 없을 수 있습니다.

### 결정

모든 선택 창은 한 가지 규칙을 따릅니다. 같은 문구의 드롭다운이고, 언제나 **"직접 입력"** 탈출구를 둡니다. 목록이 모르는 저장된
값은 그대로 보여 주고, 목록이 실제로 도착한 뒤에만 직접 입력으로 바꿉니다 — 그 전에는 절대 바꾸지 않으므로 느린 요청이 저장된
설정을 고쳐 쓰지 못합니다.

### 결과

- 가리키는 대상이 생기기 전에도 설정할 수 있고, 목록을 못 불러와도 설정이 살아남습니다.
- 모든 선택 창이 같게 동작해서 규칙을 한 번만 배우면 됩니다.
- 선택 창마다 따로 정하지 않고 코드가 공통 규칙(`picker.ts`)을 갖습니다.

## Context

The dashboard offers lists to pick from — channels, roles, members, repositories, GitHub accounts, open pull requests.
Each list can be incomplete: the App may not be installed on a repository yet, credentials may be missing, an item may
be closed, a member may not be cached.

## Decision

Every picker follows one convention: it is a dropdown with the same wording, and it always keeps a **"type it in"**
escape. A saved value the list does not know is shown as it is, and only switches the field to typed entry once the
list has actually arrived — never before, so a slow request cannot rewrite a saved setting.

## Consequences

- Settings can be made before the thing they point to exists, and survive lists that fail to load.
- All pickers behave alike, so the rule is learned once.
- The code carries the shared convention (`picker.ts`) instead of each picker deciding on its own.
