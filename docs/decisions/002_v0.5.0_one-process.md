# 002 — The bot, its API and the dashboard are one process

<details>
<summary><b>한국어 — 봇, API, 대시보드는 한 프로세스</b></summary>

- **버전:** v0.5.0
- **상태:** 채택

### 맥락

처음 계획은 디스코드 봇, 음악 작업 레지스트리와 대시보드 API를 가진 별도 HTTP 서비스, 그리고 worker로 나누는 것이었습니다.
작은 팀이 직접 운영하는 봇에게는 배포할 것이 셋이 되고, 대기 중인 작업 하나를 풀기 위해 봇과 API 사이에 통로가 필요했습니다.

### 결정

HTTP API를 **봇 프로세스 안에 넣습니다**(Node HTTP 서버 위의 Hono). 한 프로세스가 디스코드 클라이언트, 음악 플레이어, 작업
레지스트리, `/api/*` API, `/internal/*` worker 콜백, GitHub 웹훅을 갖고, 빌드된 대시보드(Vue)를 `/`에서 제공합니다.

### 결과

- worker를 뺀 모든 것이 이미지 하나, 컨테이너 하나입니다. API 핸들러가 봇의 함수를 바로 부릅니다 — 대시보드의 "건너뛰기"와
  `!skip`이 같은 코드를 실행합니다.
- 콜백은 브로커 없이 메모리에서 대기 중인 작업을 풉니다.
- 프로세스가 단일 장애점이고, 메모리에 있는 상태(작업, 대기열, 기록)는 재시작하면 사라집니다. 이 용도에서는 받아들일 만하며,
  그래서 지켜야 할 데이터는 파일([003](./003_v0.5.0_settings-in-json-files.md))로, 나중에는 데이터베이스로 갑니다.
- `/internal/*`이 공개 경로와 포트를 함께 쓰므로 리버스 프록시가 그 경로를 열면 안 됩니다.

## Context

The first plan split the system into a Discord bot, a separate HTTP service holding the music job registry and the
dashboard API, and the worker. For a small team's self-hosted bot that meant three things to deploy, and the bot and the
API needed a channel between them just to resolve a pending job.

## Decision

The HTTP API is **embedded in the bot process** (Hono on the Node HTTP server). One process holds the Discord client,
the music player, the job registry, the API under `/api/*`, the worker callbacks under `/internal/*`, the GitHub webhook,
and serves the built dashboard (Vue) at `/`.

## Consequences

- One image and one container for everything but the worker; API handlers call the bot's own functions directly — the
  dashboard's "skip" and `!skip` run the same code.
- A callback resolves a waiting job in memory, with no broker.
- The process is a single point of failure, and state that lives in memory (jobs, the queue, history) is lost on
  restart — acceptable for this use, and the reason persistent data goes to files ([003](./003_v0.5.0_settings-in-json-files.md)) and later a database.
- `/internal/*` shares the port with the public routes, so the reverse proxy must not expose it.
