# 003 — Runtime settings live in JSON files

<details>
<summary><b>한국어 — 런타임 설정은 JSON 파일에</b></summary>

- **버전:** v0.5.0
- **상태:** 채택

### 맥락

접두사, 음악 채널, 입장·퇴장 메시지, 나중에는 GitHub 라우팅과 리액션 롤 패널까지 — 모두 봇이 도는 동안 대시보드에서 바뀌어야
합니다. 코드에 박거나 환경 변수에 두면 바꿀 때마다 재시작하거나 다시 배포해야 합니다.

### 결정

런타임 설정은 기능마다 파일 하나씩, `data/` 아래 JSON 파일로 저장합니다(`runtime-config.json`, `guild-events.json`,
`github-notify.json`, `reaction-roles.json`, `github-messages.json`). 모든 로더는 파일이 없어도 동작하고, 망가진 파일은
알립니다(`loadSettingsFile`). 환경 변수에는 배포 사실과 비밀만 둡니다.

### 결과

- 돌릴 데이터베이스가 없고, 파일은 백업하기도 읽기도 쉽습니다.
- 파일마다 통째로 읽고 쓰기 때문에, 설정에는 괜찮지만 늘어나는 데이터(추적 중인 GitHub 메시지)에는 버겁기 시작합니다. 그런
  데이터는 v0.8에서 데이터베이스로 옮길 계획이며, 메시지 추적이 첫 대상입니다.
- 설정 형식은 조심해서 바꿉니다. 키 이름을 바꾸면 옛 형태를 알아보는 이전 처리가 필요합니다.

## Context

Prefix, music channels, join and leave messages, and later GitHub routing and reaction-role panels all need to change
while the bot runs, from the dashboard. Hard-coding them or keeping them in environment variables would mean a restart —
or a redeploy — for every change.

## Decision

Runtime settings persist as JSON files under `data/` (`runtime-config.json`, `guild-events.json`, `github-notify.json`,
`reaction-roles.json`, `github-messages.json`), one file per feature. Every loader tolerates a missing file and reports a
damaged one (`loadSettingsFile`). Environment variables hold only deployment facts and secrets.

## Consequences

- No database to run; the files are easy to back up and to read.
- Each file is read and written whole, which is fine for settings and starts to strain for data that grows (tracked
  GitHub messages). Moving those to a database is planned for v0.8, with the message tracker first.
- Settings formats change carefully: a renamed key needs a migration that recognises the old shape.
