# 007 — GitHub events through a GitHub App and one webhook

<details>
<summary><b>한국어 — GitHub 이벤트는 GitHub App과 웹훅 하나로</b></summary>

- **버전:** v0.6.0
- **상태:** 채택

### 맥락

팀은 PR과 Issue의 일 — 열림, 리뷰 요청, 승인, 머지 — 을 일어나는 대로 디스코드에서, 관련된 사람을 멘션하며 듣고 싶었습니다.
폴링은 늦고 낭비가 많고, 저장소마다 웹훅을 걸면 저장소마다 비밀과 프록시 규칙이 하나씩 필요합니다.

### 결정

- 이벤트 기반: 조직에 설치한 **GitHub App**이 모든 이벤트를 **하나의** 공개 경로 `POST /webhooks/github`로 보내고,
  `X-Hub-Signature-256`으로 검증합니다.
- 어느 저장소를 다룰지는 App 설치가 정합니다. Pipit은 **라우팅 표**만 가집니다 — 저장소마다 어느 채널, 어떤 이벤트인지,
  `null`은 "기본값을 물려받음".
- 멘션을 위해 GitHub 로그인을 디스코드 사용자와 연결합니다. 연결된 ID만 누군가를 부를 수 있고, 메시지에 들어가는 값은
  모두 정리(sanitize)됩니다.

### 결과

- 저장소를 추가해도 Pipit이나 프록시를 바꿀 필요가 없습니다.
- App의 자격 증명으로 필요할 때 GitHub를 읽을 수도 있게 됩니다([012](./012_v0.6.6_reminders-read-github-on-demand.md)) —
  부여받은 읽기 전용 권한 안에서.
- 전달은 App이 설치되어 있고 닿을 수 있는지에 달려 있습니다. 대시보드의 발송 기록이 무엇을 받고 보냈는지 보여 줍니다.

## Context

The team wanted to hear about pull requests and issues as they happen — opened, review requested, approved, merged —
in Discord, mentioning the people involved. Polling would be late and wasteful; a webhook per repository would mean a
secret and a proxy rule per repository.

## Decision

- Event-driven: a **GitHub App**, installed on the organisation, sends every event to **one** public route,
  `POST /webhooks/github`, verified by `X-Hub-Signature-256`.
- Which repositories are covered is decided by the App's installation; Pipit keeps only a **routing table** — which
  channel and which events per repository, with `null` meaning "inherit the default".
- GitHub logins map to Discord users for mentions; only mapped IDs can ping anyone, and everything substituted into a
  message is sanitised.

## Consequences

- Adding a repository needs no change in Pipit or the proxy.
- The App's credentials also allow reading GitHub on demand ([012](./012_v0.6.6_reminders-read-github-on-demand.md)),
  within the read-only permissions it was granted.
- Delivery depends on the App being installed and reachable; a delivery log on the dashboard shows what was received
  and what was sent.
