# 015 — The bot applies the volume itself

- **버전:** v0.7.0

### 맥락

준비된 파일은 이미 48 kHz 16비트 PCM이라 플레이어의 오디오 처리 단계를 꺼 둡니다 — 다시 처리하면 끊겼습니다. 그런데 플레이어는
볼륨 단계를 그 처리 단계 안에서만 만들기 때문에 볼륨 설정이 항상 실패했습니다. 볼륨 명령은 아무것도 바뀌지 않는데 "설정됨"이라고
답해 왔습니다.

### 결정

봇이 **자기 볼륨 단계**(낮음 / 중간 / 높음)를 들고, 모든 곡을 스트리밍하면서 샘플에 곱합니다. 단계는 청크마다 읽어서, 재생 중인
곡에도 1초 안쪽으로 반영됩니다. 봇이 통화방에 있으면 재생 여부와 상관없이 바꿀 수 있고, 다음 세션에도 이어집니다.

### 결과

- 처리 단계를 다시 켜지 않고도 볼륨이 동작합니다.
- 단계는 셋뿐이고 최대치를 넘지 않으므로 클리핑이 없습니다.
- 단계는 메모리에 있어서 재시작하면 '높음'으로 돌아갑니다.

## Context

The prepared files are already 48 kHz 16-bit PCM, so the player's processing chain is switched off — reprocessing them
caused stutter. The player builds its volume stage only inside that chain, so setting the volume always failed: the
volume command had been answering "set" while nothing changed.

## Decision

The bot keeps its **own volume level** (low / mid / high) and scales the samples of every track as it streams them,
reading the level per chunk so a change reaches a playing track within a fraction of a second. It can be set whenever
the bot is in a voice channel, playing or not, and carries over to the next session.

## Consequences

- The volume works without bringing back the processing chain.
- Only three levels, and none above full scale, so nothing clips.
- The level is in memory; a restart returns it to high.
