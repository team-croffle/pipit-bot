# 014 — The dashboard controls music as fully as the commands

- **버전:** v0.7.0
- **상태:** 채택

### 맥락

음악은 디스코드에서는 모든 조작이 가능했지만, 대시보드는 상태와 버튼 몇 개만 보여 주었습니다. 대시보드를 쓰는 사람은 통화방에
있지 않고 그 조작 뒤에 디스코드 메시지도 없어서, 명령을 그대로 옮길 수 없었습니다.

### 결정

- 대시보드가 명령이 하는 모든 일 — 목록에서 고른 통화방 참여·이동·나가기, 볼륨, 대기열의 곡마다 조작, 다음에 재생 — 을 하고,
  **명령과 API가 같은 함수를 부릅니다**.
- 대기열의 곡은 대시보드에서는 **플레이어의 트랙 id**로(목록이 폴링 한 번만큼 늦을 수 있으므로), 명령에서는 위치로
  지정합니다.
- 다른 통화방으로 옮길 때는 같은 연결로 다시 참여해서 지금 곡이 계속 재생됩니다.

### 결과

- 두 쪽의 동작이 어긋날 수 없고, 고친 것은 양쪽에 함께 들어갑니다.
- 음악 채널에 있는 누구나 명령을 쓸 수 있듯이, 음악 조작은 로그인한 누구나 할 수 있습니다. 이를 제한하는 것은 별도의
  결정입니다.
- 거절된 조작은 대시보드가 문장으로 보여 주는 이유와 함께 답합니다.

## Context

Music could be controlled from Discord in full, but the dashboard only showed the state and a few buttons. Someone
using the dashboard is not in a voice channel and has no Discord message behind their action, so commands could not
simply be mirrored.

## Decision

- The dashboard does everything the commands do — join, move and leave a voice channel chosen from a list, volume,
  every queued track with its own actions, play next — and **commands and API call the same functions**.
- Queued tracks are addressed by the **player's track id** from the dashboard (its list can be a poll behind) and by
  position from commands.
- Moving to another voice channel rejoins the same connection, so the current track keeps playing.

## Consequences

- Behaviour cannot drift between the two surfaces; a fix lands in both.
- Music controls are open to anyone signed in, as commands are open to anyone in the music channel; restricting them is
  a separate decision.
- A refused action answers with a reason the dashboard shows as text.
