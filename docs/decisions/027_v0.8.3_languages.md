- **버전:** v0.8.3

### 맥락

v0.8.1에서 결산 하나만 언어를 골랐고, 나머지는 섞여 있었습니다: 디스코드 메시지와 명령 응답은 대부분 영어, 음악 채널 배너와 대시보드는 한국어
고정. 팀은 한국어를 쓰지만 저장소는 공개이고, 영어를 쓰는 서버도 있습니다. 새 기능(v0.9 캘린더)이 처음부터 두 언어로 만들어지려면
먼저 틀이 필요했습니다.

### 결정

- **누가 보느냐로 정합니다.** 채널에 올라가는 메시지(음악 배너, GitHub 알림, 입장·퇴장 기록, 결산)는 **서버의 메시지 언어**를 따르고,
  기능마다 덮어쓸 수 있습니다. 한 사람에게만 보이는 응답(명령 응답, 리모컨 입력 창, 검색 결과)은 **그 사람의 디스코드 언어**를 따릅니다.
  대시보드는 **개인이 고른 언어 > 서버의 대시보드 기본 > 브라우저 언어** 순서입니다.
- **기본은 영어입니다.** 공개 저장소의 기본이고, 지금까지의 동작(대부분 영어)과 같습니다. 한국어 배너를 쓰던 서버는 메시지 언어를 한국어로
  바꿔야 합니다 — 노트와 README에 적었습니다.
- **설정은 파일입니다**(`data/language.json`, [024](./024_v0.8.0_database.md)의 기준). 개인 언어는 사용자에 둡니다.
- **결과는 영어 문장과 함께 "문구 키"를 싣습니다.** 같은 결과("일시정지: …")가 누른 사람의 응답, 음악 채널, 대시보드, 감사 로그로 갑니다.
  결과는 영어 `message`를 그대로 두고 키와 값을 함께 실어, 보여 주는 쪽이 언어를 고릅니다. API와 감사 로그는 영어를 유지하고,
  대시보드에 그대로 보이는 답은 요청한 사람의 언어로 바꿔 돌려줍니다.
- **운영자가 쓴 글은 번역하지 않습니다.** GitHub 템플릿, 입장 메시지, 리액션 롤 패널은 쓴 그대로 보냅니다. 봇이 넣는 말 — 기본 템플릿의 칸
  이름, `{event}` 라벨 — 만 언어를 따릅니다. `{event}`는 고친 템플릿 안에서도 번역됩니다.
- **슬래시 명령은 설명만 두 언어로 등록합니다.** 이름까지 바꾸면 사람마다 명령이 달라 보여 안내가 어려워집니다.
- **라이브러리**: 봇은 i18next(결산에서 쓰던 그대로), 대시보드는 vue-i18n. 리소스는 둘 다 TypeScript 모듈, 기능마다 파일 하나.

### 결과

- 새 문구는 처음부터 두 언어 리소스에 넣습니다(AGENTS.md §4). 언어를 하나 더하려면 리소스를 늘리면 됩니다.
- 로그, 감사 로그, 배달 기록은 영어로 남습니다.
- 연말 재생목록 이름(`2026 결산`)은 데이터 이름이라 언어를 따르지 않습니다.

## Context

In v0.8.1 the recap alone chose a language, and the rest was mixed: Discord messages and command replies mostly English,
the music channel's banner and the dashboard Korean only. The team writes Korean, but the repository is public and other
servers speak English. New features (v0.9's calendar) needed a frame to be built in both languages from the start.

## Decision

- **Who reads it decides.** Messages posted to a channel (the music banner, GitHub notifications, the join and leave
  record, recaps) follow the **server's message language**, which each feature can override. Replies only one person
  sees (command answers, the remote's forms, search results) follow **that person's Discord language**. The dashboard
  follows **the person's own choice, then the server's dashboard default, then the browser**.
- **English by default** — the public repository's default and what most of the bot already said. A server that relied
  on the Korean banner sets the message language to Korean; the notes and README say so.
- **Settings are a file** (`data/language.json`, the line [024](./024_v0.8.0_database.md) drew); a person's own language
  is kept on the user.
- **A result carries a phrase beside its English sentence.** The same result ("Paused: …") goes to the person who
  pressed, the music channel, the dashboard and the audit log. It keeps its English `message` and carries a key with its
  values, and whoever shows it picks the language. The API and the audit log stay English; an answer the dashboard shows
  as it is comes back in the requester's language.
- **An operator's wording is not translated.** GitHub templates, join messages and reaction-role panels go out as
  written; only the bot's own words — the built-in templates' field names, the `{event}` label — follow the language.
  `{event}` is translated inside an operator's template too.
- **Slash commands register their descriptions in both languages, not their names** — names that differ by person would
  make instructions hard to give.
- **Libraries**: i18next in the bot (as the recap already used), vue-i18n in the dashboard; resources are TypeScript
  modules, one file per feature, in both.

## Consequences

- New copy goes into both resources from the start (AGENTS.md §4); another language means more resources.
- Logs, the audit log and delivery records stay English.
- The year's playlist name (`2026 결산`) is data and does not follow the language.
