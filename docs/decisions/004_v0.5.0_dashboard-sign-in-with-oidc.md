# 004 — The dashboard signs in with OIDC, as its own client

- **버전:** v0.5.0
- **상태:** 채택

### 맥락

대시보드는 서버 전체의 봇 동작을 바꾸므로 제대로 된 로그인과, 보기만 하는 사람과 설정을 바꾸는 사람의 구분이 필요합니다. 앞에
인증 리버스 프록시를 두면 운영할 서비스가 하나 늘고, 앱이 사용자의 신원을 볼 수 없게 됩니다.

### 결정

앱이 직접 **OIDC 클라이언트**가 됩니다(PKCE를 쓰는 Authorization Code, `openid-client`). 쓰기 권한은 신원 공급자의 그룹에서
옵니다(`DASHBOARD_ADMIN_GROUPS`를 `groups` 클레임과 대조). 로그인한 사람은 누구나 보고 재생을 조작할 수 있습니다. 발급자가
설정되지 않으면 개발용 신원이 적용됩니다.

### 결과

- 표준을 따르는 공급자면 무엇이든 동작하고, 앱 앞에 다른 것이 없습니다.
- 세션과 콜백 처리는 앱의 몫이며, 리버스 프록시 뒤에서도 둘 다 올바르게 유지해야 합니다.
- 권한 모델은 그룹뿐입니다 — Pipit 안에 사용자별 역할은 없습니다.

### 이후

v0.6.7에서 클라이언트를 공급자 중립으로 만들었습니다. 요청 scope를 설정할 수 있게 했고(`OIDC_SCOPES`, 기본
`openid profile email groups` — 요청해야만 groups를 보내는 공급자가 이유였습니다), 공급자에 닿지 못하면 맨 `500` 대신 원인을
담은 `502`로 답합니다.

## Context

The dashboard changes how the bot behaves for a whole server, so it needs real sign-in and a distinction between people
who may look and people who may change settings. An authenticating reverse proxy in front of it would be one more
service to run and would hide the user's identity from the app.

## Decision

The app is an **OIDC client** itself (Authorization Code with PKCE, `openid-client`). Write access maps from identity
provider groups (`DASHBOARD_ADMIN_GROUPS`, matched against the `groups` claim); anyone signed in may view and control
playback. With no issuer configured, a development identity applies.

## Consequences

- Any standards-compliant provider works; nothing else sits in front of the app.
- The app owns sessions and callback handling, and must keep both correct behind a reverse proxy.
- Groups are the only permission model — there are no per-user roles inside Pipit.

## Later

v0.6.7 made the client provider-neutral: the requested scopes became configurable (`OIDC_SCOPES`, default
`openid profile email groups` — a provider that only sends groups when asked was the reason), and an unreachable
provider answers `502` with its cause instead of a bare `500`.
