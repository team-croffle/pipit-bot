### 맥락

웹훅은 무엇이 일어났는지를 말할 뿐, 무엇이 아직 남았는지는 말하지 않습니다. 팀은 PR이나 Issue가 기다리는 사람을 — 요청하면,
며칠 뒤에라도 — 다시 부르고 싶었는데, 저장된 웹훅 기록은 "지금 누구를 기다리나?"에 답할 만큼 완전하지도 최신이지도
않았습니다.

### 결정

`!remind owner/repo #12`(와 대시보드 카드)는 그 순간 **App의 REST 접근으로 GitHub에서 항목을 읽습니다**. PR이면 남은 리뷰어와
담당자, Issue면 담당자를 저장소 채널에서 부릅니다. 초안이거나 기다리는 사람이 없으면 부르지 않고 이유를 답하고, 닫히거나 머지된
항목은 알림 메시지만 갱신합니다. 항목마다 짧은 대기 시간이 있습니다.

### 결과

- 놓친 웹훅이 있어도 리마인더는 언제나 최신입니다.
- 이제 Pipit이 GitHub를 호출하므로 설치 토큰이 필요하고, 목록을 잠깐 캐시하며, 설치나 권한이 없으면 그대로 알립니다.
- 같은 접근이 대시보드의 저장소·멤버·열린 항목 목록에도 쓰입니다([013](./013_v0.6.8_lists-are-not-authoritative.md)).

## Context

Webhooks say what happened, not what is still pending. The team wanted to nudge the people a pull request or issue is
waiting on — on request, days later — and the stored webhook history was neither complete nor current enough to answer
"who is it waiting on now?".

## Decision

`!remind owner/repo #12` (and a dashboard card) **reads the item from GitHub through the App's REST access** at that
moment: for a pull request the pending reviewers and assignees, for an issue the assignees, and calls them in the
repository's channel. Drafts and items with nobody to wait on get a reason instead of a ping; closed or merged items only
refresh their announcement. Each item has a short cooldown.

## Consequences

- Reminders are always current, whatever webhooks were missed.
- Pipit now calls GitHub, so it needs installation tokens, caches lists briefly, and reports a missing installation or
  permission plainly.
- The same access feeds the dashboard's lists of repositories, members and open items
  ([013](./013_v0.6.8_lists-are-not-authoritative.md)).
