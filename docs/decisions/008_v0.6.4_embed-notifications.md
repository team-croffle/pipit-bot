# 008 — Notifications are templated embeds; mentions stay outside

- **버전:** v0.6.4

### 맥락

첫 알림은 평문 한 줄이었습니다. 디스코드 임베드 안의 멘션은 이름으로 보이기만 하고 아무에게도 알림이 가지 않는데, 사람에게
알리는 것이 핵심이었기 때문입니다. 하지만 평문으로는 제목·필드·색을 담을 수 없었고, 팀은 이벤트마다 문구를 다르게 쓰고
싶었습니다.

### 결정

알림은 **임베드**이고 그 **위에 평문 한 줄**이 있습니다. 멘션은 알림이 가는 평문 줄에, 나머지는 임베드에 둡니다. 모든 부분이
대시보드에서 실시간 미리보기와 함께 편집하는 템플릿이고, 이벤트마다 채울 수 있는 값만 제공합니다. 치환되는 값은 이스케이프되어
PR 제목으로 멘션이나 링크를 위조할 수 없습니다.

### 결과

- 문구는 코드가 아니라 설정이고, 기본값은 봇과 함께 배포됩니다.
- 같은 임베드 편집기를 리액션 롤 패널에도 씁니다.
- 템플릿 문법과 이벤트별 값 목록은 대시보드와의 계약입니다. SPA에 따로 두지 않고 API가 내려 줍니다.

## Context

The first notifications were plain lines, partly because a mention inside a Discord embed shows as a name but notifies
no one — and notifying people was the point. Plain lines, though, could not carry a title, fields and colour, and the
team wanted to word each event its own way.

## Decision

Notifications are **embeds** with a **plain line above them**: mentions go in the plain line, where they notify;
everything else goes in the embed. Every part is a template edited on the dashboard with a live preview, and each event
offers only the values it can fill. Substituted values are escaped, so a pull request title cannot forge a mention or a
link.

## Consequences

- Wording is configuration, not code; defaults ship with the bot.
- The same embed editor serves reaction-role panels.
- The template language and the per-event value lists are a contract with the dashboard; they are served by the API
  rather than duplicated in the SPA.
