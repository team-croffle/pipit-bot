# 017 — Slash commands only, and a remote control in the music channel

<details>
<summary><b>한국어 — 슬래시 명령만, 그리고 음악 채널의 리모컨</b></summary>

- **버전:** v0.7.1 (프리릴리즈)
- **상태:** 채택

### 맥락

음악 채널은 `!p`, `!skip` 같은 명령과 그 답으로 금방 어지러워졌고, 답은 채널의 모두에게 보였습니다. 팀은 채널을 메시지 하나 —
지금 무엇이 나오는지와 조작 버튼 — 로 유지하고, 조작의 결과는 조작한 사람에게만 보이길 원했습니다. 디스코드는 *일반 메시지*에는
본인만 보는 답을 보낼 수 없고, 슬래시 명령·버튼·입력 창 같은 interaction에만 보낼 수 있습니다.

### 결정

- **명령은 모두 슬래시 명령**이고 답은 본인만 봅니다. `!` 메시지 명령과 **명령 접두사 설정은 없앱니다**. 겹치던 명령은 합칩니다
  (`/play query [next]`, `/skip [to]`). 명령은 전역으로 등록하되 서버 안에서만 쓰입니다 — 레지스트리가 채워질 때는 서버 ID를 모르고,
  Pipit은 서버 하나에서 돌기 때문입니다.
- 설정된 음악 채널마다 봇이 **리모컨 배너** 하나를 Components V2로 유지합니다. 대기 화면은 곡을 요청하는 방법과 재생 버튼, 재생 중
  화면은 곡·신청한 사람·진행·상태와 조작 버튼입니다. 버튼 결과는 누른 사람에게만 5초 보입니다.
- 음악 채널에 **친 한 줄은 곡 요청**입니다. 처리한 뒤 원문을 지우고, 결과는 모두에게 보이는 짧은 배너로 알린 다음 지웁니다 — 일반
  메시지에는 본인만 보는 답이 불가능하기 때문입니다.
- 배너는 이벤트를 하나하나 걸지 않고 재생 상태를 몇 초마다 비교해, 보여 주는 내용이 바뀔 때만 다시 그립니다.

### 결과

- 음악 채널이 배너 하나로 유지되고, 명령·버튼·대시보드가 같은 함수를 부르므로 어디서 조작해도 결과가 같습니다.
- 운영자는 봇을 `applications.commands` scope로 다시 승인하고, 음악 채널에서 메시지 관리 권한을 주어야 합니다. 권한이 없어도 요청은
  처리되고 줄만 남습니다.
- `!` 습관은 `!p`·`!play` 뒤를 요청으로 받아 주고, 다른 `!` 줄은 슬래시 명령을 안내합니다.
- 조작 결과 문구는 아직 서버 쪽 영어 문장입니다.

## Context

The music channel filled up quickly with `!p`, `!skip` and their answers, and every answer was visible to everyone in
the channel. The team wanted the channel to hold one message — what is playing, and the controls — with the result of
an action shown only to whoever took it. Discord can answer privately only to an interaction (a slash command, a button,
a dialog), never to a plain message.

## Decision

- **All commands are slash commands**, answered so only the person who used one sees the answer. The `!` message
  commands and the **command prefix setting are removed**; overlapping commands merge (`/play query [next]`,
  `/skip [to]`). Commands are registered globally but usable only inside the server — the registry fills before the
  server's id is known, and Pipit runs in one server.
- Every configured music channel holds one **remote-control banner** in Components V2: idle, how to request a track
  and a play button; playing, the track, who asked, progress, status and controls. A button's result is shown only to
  the person who pressed it, for five seconds.
- A **line typed into a music channel is a request**: it is handled, the line is removed, and a short banner everyone
  can see gives the result and then removes itself — a plain message cannot be answered privately.
- The banner compares the playback state every few seconds and is redrawn only when what it shows changed, rather than
  hooking every action.

## Consequences

- The music channel stays one banner, and since commands, buttons and the dashboard call the same functions, an action
  behaves the same wherever it is taken.
- Operators have to authorise the bot again with the `applications.commands` scope and give it Manage Messages in the
  music channel; without that permission requests still run and the line stays.
- The `!` habit is met halfway: what follows `!p` or `!play` is taken as a request, and any other `!` line is pointed
  at the slash commands.
- Result messages are still the server's English sentences.
