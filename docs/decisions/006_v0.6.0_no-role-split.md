# 006 — No main / edge split

<details>
<summary><b>한국어 — main / edge 분리 없음</b></summary>

- **버전:** v0.6.0
- **상태:** 채택

### 맥락

초기에는 봇이 두 역할 — main 인스턴스와 다른 곳의 "edge" 노드 — 로 돌 수 있었고, 명령은 한쪽 역할로 제한되었습니다. edge 노드는
디스코드 봇이 될 일이 없었습니다. 그 노드가 맡으려던 일은 이 저장소 밖의 별도 프로젝트에 속합니다.

### 결정

역할 분리를 완전히 없앴습니다. `ROLE` 설정도, main 전용·edge 전용 전제 조건도 없습니다. Pipit은 서버마다 배포 하나입니다.

### 결과

- 설정과 코드가 단순해지고, 모든 명령이 봇이 도는 어디서나 동작합니다.
- 역할이나 그 비슷한 것을 다시 들이는 일은 여기서 배제합니다 — 그런 일은 Pipit 밖에서 다룹니다.

</details>

## Context

Early on, the bot could run in two roles — a main instance and "edge" nodes elsewhere — with commands restricted to one
role or the other. Edge nodes were never going to be Discord bots: the work they were meant for belongs to a separate
project outside this repository.

## Decision

The role split was removed entirely: no `ROLE` setting, no main-only or edge-only preconditions. Pipit is one deployment
per server.

## Consequences

- Simpler configuration and code; every command runs everywhere the bot runs.
- Reintroducing roles, or anything like them, is ruled out here — work of that kind is handled outside Pipit.
